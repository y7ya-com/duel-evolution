# Browser audio integration

Exports from `features/audio`: `BrowserAudioManager`, `AUDIO_SLOTS` (46 source slot descriptors), `BrowserAudioOptions`, `AudioState`, `AudioAction`, `AudioSlotMode`, `AudioStorage`, `AUDIO_FILE_LIMITS`. `features/audio-storage` additionally exports `IndexedDBAudioStorage`, `StoredAudio`, `StoredAudioSlot`, `validateStoredAudio`.

Create one manager per app lifetime. **At boot, explicitly call `await manager.restore()` before enabling audio settings mutations.** Rerender audio settings from `manager.getState()` afterward. Restore never constructs/resumes an AudioContext or starts media playback. The app still selects the scene using `playSlot`. Invoke `activate()` directly inside the originating trusted click/keydown handler, with no preceding await: context resume and media play both begin synchronously in that handler. Call `dispose()` on teardown. Constructor and rendering are inert.

Public contract (existing methods/commands remain compatible):

- `restore(): Promise<boolean>`: read and validate optional local IndexedDB state atomically. True means successful restoration, including an empty database. False means disabled/unavailable/failed storage or a stale read superseded by local edits/disposal. Concurrent calls share one read; success is idempotent. Failures can be retried. Any local settings edit before/during restoration takes precedence over the entire stored snapshot; restore after edits returns false. Scene selection/stop does not mutate stored settings.
- `setSlotFiles(slot: number, files: File[]): void`: atomically replace a local playlist, `[]` deletes that slot's file assignment. Plays the reassignment immediately if relevant to the current scene. Unrelated changes do not restart completed jingles. Empty slots follow fallback rules below. Invalid slots/files/limits throw before changing assignments. Saves automatically in the background.
- `setSlotMode(slot: number, {shuffle?, loop?, volume?}): void`: set per-slot modes, defaults false/source loop flag/1. Shuffle uses a Fisher–Yates permutation, once at start and again each loop cycle; every file occurs once per cycle. Sequential mode preserves assigned order. Loop false stops after the final track, true repeats; one repeating track uses native media looping. Shuffle/loop changes restart that slot if playing; volume-only changes apply live. Invalid edits are atomic. Modes persist even for empty slots.
- `playSlot(slot: number): Promise<boolean>`: select scene audio without activating. True means started/already playing, not proof of audible output. Repeated calls do not restart completed jingles.
- `setVolumes({music?, sound?}): void`: independent normalized 0–1 volume, persisted; invalid values throw. Music output multiplies music master and slot volume.
- `flushPersistence(): Promise<void>`: wait for outstanding/coalesced saves. Storage errors are reported through state and `onError`, rather than thrown or used to undo live assignments. Await before an intentional reload if durability matters; synchronous dispose cannot guarantee a final save.
- `playEffect(path: string): Promise<boolean>`: read supplied `SE/*.wav` from a Sound.dat range reader/URL and decode. Missing/unsupported files return false and report via optional `onError`.
- `stop(): void`: invalidate pending playback and stop music/effects; retain files, modes, cache, persisted data and activation.
- `dispose(): void`: idempotent stop, detach media handlers, pause/remove/load media, revoke live object URL, cancel storage/archive work, close owned storage and AudioContext, release references/cache. Stored assignments survive disposal.

`getState()` returns detached metadata. It adds `persistence: {status, error?}` with status `disabled | idle | restoring | saving | ready | error`, and each slot includes effective `loop`, `shuffle`, `volume`, plus filenames. These additions are optional in the public state interface for compatibility with pre-existing UI snapshots, but the manager always emits them. State-driven callers rerender after restore/dispatch/flush settles; there is no automatic subscription. `getSlotFiles(slot)` returns a copied File list; `volumes`, `currentSlot`, `isActivated`, `decodedBytes` remain read-only.

`dispatch(action): Promise<void>` accepts existing `activate`, `stop`, `play-slot`, `set-slot-files`, `set-volumes`, plus `{type:'restore'}` and `{type:'set-slot-mode',slot,shuffle?,loop?,volume?}`. `play-slot` dispatch is the UI preview action and activates directly in the handler; ordinary scene transitions must call `playSlot`. Dispatch does not wait for persistence. Controller code must call manager.dispatch before its first await to retain user activation. Existing `renderAudioFeature(manager)` and state/dispatch overloads need no changes; additional mode/status controls belong to UI integration.

Storage defaults to IndexedDB database `duel-evolution-local-audio-v1`, store `audio`, key `state`, schema version 1. Files, filenames, per-slot choices and both master volumes are written as a single atomic snapshot. No current scene/preview/activation is restored. `storage: false` disables persistence. Missing IndexedDB disables it; access/open/quota/transaction failures leave playback and local settings usable and are surfaced in state/`onError`. Browser storage may be evicted; a failed deletion/reassignment save leaves the prior disk snapshot intact. A later edit retries saving the latest state. Other tabs use last completed write wins; cross-tab merging is not implemented.

Inject `storage: AudioStorage` for tests/custom storage; manager owns and closes it. The adapter has `read(signal): Promise<unknown>`, `write(StoredAudio, signal): Promise<void>`, `close(): void`. Implementations must honor cancellation and close to prevent late commits. The default adapter aborts active transactions, checks cancellation after database open, and closes late-opened databases. No server upload, archive song copying, base64 conversion, `File.arrayBuffer()`, or redundant Blob wrapping occurs in persistence/playback. One save runs at a time; edits coalesce into one latest snapshot. Files themselves are immutable references until browser structured clone. IndexedDB's temporary serialization/storage allocations are browser-owned; the limits bound accepted assignments, not browser-internal allocations or a manually corrupted database's deserialization before validation.

Assignment limits: **8 files per slot, 64 MiB per file, 256 files and 256 MiB total**, counting repeated assignments separately; filenames at most 4096 characters. Validation runs before mutation and after storage reads, including modes, duplicate slots, counts and bytes. Restored snapshots are applied all-or-nothing. No full-file reads are needed to enforce limits.

Music uses one streaming HTMLAudioElement and one short-lived object URL with immediate transitions. Empty 24/25/30–45 use the last requested 10–20 duel base; empty 21–23 leave current audio alone. Media errors skip at most a playlist's length of consecutive failures. Unsupported-codec play rejections advance; autoplay/other play rejections stop and require a later gesture to retry. Old media/activation promises cannot stop newer playback. Effects duck music immediately to 35% while any effect plays; sound volume zero disables effect work.

Pass `soundArchiveUrl` for a deployment's actual Sound.dat range endpoint, or `archive: {read(path, signal)}` from ArchiveReader. No default URL is assumed. An injected archive remains caller-owned. The original configured host lacks browser CORS, so browser reads require a deployment-authorized same-origin/CORS endpoint. Effects are explicit asset paths, never guessed server messages. Effect limits remain: 16 MiB decoded cache plus active buffers (configurable up to 64 MiB), 8 MiB decoded/4 MiB encoded per effect, four pending distinct serial decodes, 16 live voices. Browser-internal decode allocations cannot be cancelled mid-decode; late results are discarded after disposal.

## Verification and remaining timing gaps

Focused tests in `tests/audio*.test.ts` plus existing `tests/features-audio*.test.ts` cover persistence round-trip, malformed snapshots, assignment byte/count limits, coalesced writes, deletion/reassignment, quota failure/retry, stale restore/disposal, mode ordering/loop/shuffle, stale activation, media/effect budgets and fallback. `audio-browser.test.ts` launches the repository CDP helper (no preview tools), serves transpiled owned modules and existing archive dependencies over an ephemeral fixture server, and uses generated PCM silence. Real Chromium verifies IndexedDB File bytes/names/modes/volumes across manager lifetimes, transaction cancellation, no playback before activation, trusted-click WAV playback, persisted deletion, and URL revocation. No proprietary audio or full archive downloads are involved. It is opt-in: run `AUDIO_BROWSER_SMOKE=1 node tools/run.mjs vitest run tests/audio-browser.test.ts` from the experimental client directory. It requires the helper's cached Chromium or CHROME override; ordinary unit runs skip it. This is a lifecycle/one-codec smoke test, not a device/autoplay-policy matrix or gameplay parity proof.

Exact original behavior still missing: original background fade frame durations (including minimum five frames and duel advantage/pinch fade 15), original sample loop points and source 0–127 track gains, effect-ID-to-path tables and the 385 original call-site/frame cues, scripted ritual/summon timing and scene exit stop-all/fade timing. Current effects begin when explicitly requested after asynchronous range fetch/decode, with no sample/frame scheduling or latency compensation; ducking/release is immediate and follows browser onended timing, not verified original mix envelopes. The app owns scene mapping and authoritative event integration. No original songs are bundled; user playlists retain source slot defaults and documented fallback/ordering behavior only.
