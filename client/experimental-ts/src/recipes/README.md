# Private recipe catalog

`RecipeCatalog.fromJSON(input)` or `new RecipeCatalog().install(input)` validates an atomic catalog. `available(pbin: Uint8Array | null, freeMode = false)` returns fresh `{ id: string, name, main, side, extra }[]` suitable for `DeckEditorView.recipes`. `size` and `clear()` support loading and disposal. No caller-owned arrays survive installation or projection.

The version-1 JSON envelope is `{ version: 1, deckSource: 'original-ydc', recipes: [{ id: string, name: string, recipeBit: number | null, main: number[], side: number[], extra: number[] }] }`. A null right is unknown and never available. Invalid PBIN lengths return no recipes. Right numbers are zero-based, LSB first; 0x3114 must supply exactly 128 bytes. The current nine products use receipt bits 769, 771, 773, 775, 777, 779, 781, 793 and 795 (bytes 96–99); require the full frame rather than accepting a short slice.

Run `node tools/recipes.mjs` from the experimental client to create `public/deck-recipes.json`, **after the parent task adds that exact path to the client's ignore rules**. The generator refuses an unignored, tracked, existing or symlink destination (including symlink parents). It also accepts `<ignored-output.json> <server-directory>` for private validation. It reads bounded `gamedata/{ydc,shop,persist}.json` and `src/game/starter.ts`; it never executes the source or accesses the original asset host. Generated records must stay private and untracked.

Evidence and choices:

- `server/src/game/persist.ts`: `PBIN_SIZE = 128`, `pbinBytes` writes `arr[b >> 3] |= 1 << (b & 7)`. `recipeBit(deckId)` returns the shop right plus one; no mapping means no right.
- `server/src/game/shop.ts`: kind-1 structure purchases derive receipt bits from `shop.packs`, deduplicate them, and call `pbinSet`. Duplicate cart rows combine quantities while the entitlement remains a single bit.
- `server/src/game/starter.ts`: successful `starterClaim` grants that same recipe bit. `starterRecipeFix` repairs an older claim at the next PBIN request.
- Static original PE SHA-256 `d25d4b135602eafe9db1a709ac5d2367295ba1dad084366d37a1a7577021e613`: `0x00983c80` walks the pack map, selects types 1 and 4, increments the record's right, tests it through `0x00406f8c`, and appends only owned records. The type-1 branch tests at `0x00983cc5–0x00983cd3`; the type-4 branch at `0x00983cf4–0x00983d02`. It does not expose every YDC file merely because it exists. This PE was inspected statically only.
- Native `client/src/Deck/DeckEntryMain.cpp::pollRecipeList` loads the pack's original YDC. The generator therefore preserves `gamedata/ydc.json` sections, card order and repeated copies. It never applies `legalDeck`, whose substitutions belong to the acquired starter claim. The app should use its existing `expandStarterDeck` on that separate claim response.
- Names come from the source `STARTER_DECKS` literals, documented there as matching original `packinfo_e.txt`. Parsing never evaluates TypeScript. Output sorts by numeric pack ID to match the native map traversal.
- `persist.default_pbin_bits` grants none of the current nine recipe receipt bits: no built-in recipes are proven by these server defaults. `freemode.ts` expands card ownership, while `persist.h_getpbin` still sends the character's ordinary PBIN. `freeMode` consequently does not bypass recipe ownership.

Scope: the generator emits the nine source-proven shop products with names, original YDC and recipe-right mappings. Other archived YDC files, prize/NPC decks and unsold structures are deliberately excluded: file existence provides neither a proven name nor an ownership right. Supporting additional native PACK-table entries requires private source metadata and verified rights; this implementation does not invent built-in ownership. UI/app loading and the session's PBIN storage belong to the parent task.

Verification: run `node tools/run.mjs vitest run tests/recipes*.test.ts` for synthetic validation and output guards. `DE_RECIPE_PRIVATE=1 node tools/run.mjs vitest run tests/recipes-private.test.ts` additionally compares all nine original YDC lists, names and server receipt bits, demonstrates the real legal-starter difference, and exercises actual server starter claim and shop purchase handlers (including duplicate claims/cart rows, card multiplicities and receipt-bit deduplication). These tests do not snapshot game-derived records or launch Chromium.
